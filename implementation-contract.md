# Experiment 3 internal implementation contract

Services use stdlib, an sqlite3 connection with Row factory, and active transaction controlled by server. No commit or rollback in service functions. Parameterized SQL. Return JSON-compatible values. Timestamps INTEGER Unix seconds in UTC. Status strings in English below; UI translates. Python modules under campus_trade; import from .core. Date filters logs YYYY-MM-DD Beijing time.

Core imports:
- ApiError(status, message, code="bad_request"). Use 400 invalid, 401 login, 403 permission, 404 absent/hidden, 409 conflict.
- Context(account_id: int | None = None, role: str = "guest", ip: str = "127.0.0.1", must_change: bool = False, timestamp: int | None = None). ctx.now property, fixed per request if supplied; roles guest/member/admin/super; current account from session. System Context() with no actor.
- require_member(ctx), require_admin(ctx), require_login(ctx) return int actor id, raise when unauthorized/initial password pending. require_admin accepts super.
- text(value, label, maximum=500, *, required=True) returns stripped str or raises.
- integer(value, label, *, minimum=1, maximum=2147483647) handles only int and digit strings, excludes bool.
- audit(db, ctx, action, *, object_type=None, object_id=None, product_id=None, before=None, after=None, success=True, detail=None). Request-level failure audit handled by server after rollback, use success audit on meaningful service writes. Never log secrets.
- notify(db, recipient_id, event_key, message, timestamp) idempotent by recipient and event. Product/reservation keep notices in same transaction.
- Accounts table account(id, phone, nickname, password_hash, role, must_change, avatar, bio, created_at); no secrets in JSON. Categories table category(id,name) maintained by core schema seeded 1 教材与书籍, 2 数码配件, 3 宿舍用品, 4 运动户外, 5 其他.

Product module exports and HTTP maps:
- list_products(db,ctx,params): GET /api/products?scope=public|mine|admin&q=&category_id=&minimum=&maximum=&status=&sort=newest|oldest|price_asc|price_desc&page=1. minimum/maximum integer cents. Returns {"items":[product...], "page":1, "total":n, "page_size":20}.
- product_detail(db,ctx,product_id): GET /api/products/{id}; returns product.
- get_photo(db,ctx,photo_id) -> (mime:str, data:bytes): GET /api/photos/{id}. Honor product visibility and pending/proposed images admin/owner only.
- create_draft(db,ctx,data): POST /api/products. edit_product(db,ctx,product_id,data): POST /api/products/{id}/edit. Data {"title":str,"description":str,"category_id":int,"price_cents":int,"location":str,"condition":str,"contact":str,"photos":[{"mime":"image/png" or "image/jpeg","data":"BASE64"}],"version":int for edit}. Omitted fields retained on edit, title only allowed for draft. Empty photos [] removes; absence keeps. Return updated product.
- submit_product(db,ctx,product_id,data): POST /api/products/{id}/submit body {"version":int}. downlist_product(db,ctx,product_id,data): POST /api/products/{id}/downlist body {"version":int}.
- review_queue(db,ctx,params): GET /api/admin/reviews -> {"items":[review...]}; each row include id, product_id, title, kind and status. review_product(db,ctx,review_id,data): POST /api/admin/reviews/{id} body {"decision":"approve" or "reject","reason":str}.
- report_product(db,ctx,product_id,data): POST /api/products/{id}/report body {"reason":str}. report_queue(db,ctx,params): GET /api/admin/reports -> {"items":[...]}, id/product_id/title/reason/status. handle_report(db,ctx,report_id,data): POST /api/admin/reports/{id} body {"decision":"dismiss" or "violate","reason":str}. violate_product(db,ctx,product_id,data): POST /api/admin/products/{id}/violate body {"reason":str}. submit_appeal(db,ctx,product_id,data): POST /api/products/{id}/appeal body {"reason":str,"version":int}; uses review queue type appeal.
- Table and product JSON keys: product(id, seller_id, category_id nullable, title, description, price_cents nullable, location, condition, contact, status, version NOT NULL, created_at, updated_at, published_at nullable, first_published_at nullable, sold_at nullable, hidden NOT NULL DEFAULT 0); statuses draft, pending_review, published, rejected, downlisted, reserved, sold, violation. list/detail product includes photos [{"id":int,"url":"/api/photos/{id}"}] where visible, seller_name when available. Data definitions can add columns but keep names above. Violation table named violation(id, product_id, actor_id, reason, created_at); seller derived from product. Violate should call reservations.invalidate_for_violation(db,ctx,product_id,reason) first in same transaction, then update product status/hidden/version and log; for sold preserve status and sold_at but set hidden=1.

Reservation module and routes:
- create_reservation(db,ctx,product_id,data): POST /api/products/{id}/reserve with {"version":int,"request_key":str}. Returns reservation object.
- list_reservations(db,ctx,params): GET /api/reservations?scope=buyer|seller|admin&status=&page=1 -> {"items":[...],"page":1,"total":n,"page_size":20}; statuses pending, confirmed, canceled, rejected, completed. Each item keys id, product_id, buyer_id, seller_id, status, product_title, price_cents, created_at, confirmed_at, ended_at, reason. May include other info; retain historical price/title.
- reservation_action(db,ctx,reservation_id,action,data): POST /api/reservations/{id}/{action}, action confirm/reject/cancel/complete, data {"request_key":str,"reason":str optional}. Returns reservation.
- expire_due(db,ctx) -> count; background scheduler and server may call. invalidate_for_violation(db,ctx,product_id,reason) updates active reservations and notices only; product service sets product status.
- SQL stats interface: reservation(id, product_id, buyer_id, status, created_at, confirmed_at, ended_at, reason, ...); completed rows ended_at is finish. Product trigger/status invariants maintained in one transaction. Request idempotency keyed actor/action/request_key; save/replay original successful JSON. Use partial UNIQUE index and product version changes for actual transitions.

Auth and operations server implemented by root:
- GET /api/me -> {"account": null or {"id","phone","nickname","role","must_change","bio","avatar"},"categories":[{"id","name"}]}
- POST /api/auth/code {"phone"}; returns {"message":...,"development_code":str} for local simulation. POST /api/auth/register {"phone","nickname","password","code","bio"?,"avatar"?}; returns {"message":...}. POST /api/auth/login {"phone","password"} sets cookie, returns {"account":...}; POST /api/auth/logout {}; POST /api/auth/password {"old_password","new_password"}; POST /api/auth/profile {"nickname","bio","avatar"}; POST /api/admin/accounts {"phone","nickname","password"} super only, forced initial password change; GET /api/admin/accounts super only {"items":[account...]}. Never send hashes.
- GET /api/stats?scope=mine|admin; mine -> {"scope":"mine","published":int,"completed":int,"reservations":int}; admin -> {"scope":"admin","total_products":int,"categories":[{"name","count"}],"statuses":[{"status","count"}],"daily":[{"date","reservations","completed"}],"violations":[{"account_id","nickname","count"}]}. Recent 7 days Beijing time.
- GET /api/notifications -> {"items":[{"id","message","created_at","read"}]}; POST /api/notifications/{id}/read {}; GET /api/logs?scope=mine|admin&start=&end=&actor_id=&action=&product_id=&page= returns {"items":[{"id","action","object_type","object_id","product_id","actor_id","before","after","success","detail","ip","created_at"}],"page":1,"total":int,"page_size":20}; personal entries omit ip.
- HTTP errors status code + JSON {"error":str,"code":str}. JSON success structures as above; routes with POST use Content-Type application/json. GET reads public available without account. First-login state blocks protected operations. HTTP host local loopback only, no external assets.
